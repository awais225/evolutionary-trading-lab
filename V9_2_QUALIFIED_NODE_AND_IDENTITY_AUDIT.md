## Signed offsets / migration
Independent SL/TP `+ve`/`-ve` selectors express distance from entry: `+ve` farther, `-ve` closer, for BUY and SELL. Defaults are SL `+ve`, TP `-ve`; zero leaves the strategy level unchanged. Magnitude is in the established broker-derived pip convention; precision, placement, stop and freeze constraints still use the original validators.

Legacy stored signed-number values remain intact. Their old meaning is decoded into the new signs without changing execution: old positive SL→`+ve`, old negative SL→`-ve`; old positive TP→`-ve`, old negative TP→`+ve`. Old API clients and typed negative-number compatibility retain their old semantics. New explicit signs/version are additive columns and save only that node's requested values. Nonfinite offsets and invalid signs are rejected. No risk/sizing or account-selection rules changed.

The old V7 blanket prohibition on editing any live module necessarily conflicted with V9.2's explicitly requested offset/scenario/log work. Its replacement still forbids changes to broker execution/status modules and compares **every live function's AST** against V8 after narrowly removing just the requested sign arguments, entry-rule gate and truthful logging fields. The database writer's original fields/defaults and real order/account functions remain AST-protected. Assertions are not deleted or skipped to ship requested behavior.
