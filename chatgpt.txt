=============================================================
1. PROJECT IN ONE PARAGRAPH
=============================================================

Evolutionary Trading Research Lab is a local Windows research dashboard for evolutionary algorithm based trading strategy discovery.

The system generates large populations of trading strategy "nodes", evaluates/backtests them, records their genomes and economics, tracks ancestry and generations, filters and qualifies candidates, validates promising strategies, and eventually sends selected strategies into simulated/paper/MT5 testing.

The long term objective is NOT simply to generate the highest backtest return.

The objective is:

    Generate
      -> Persist
      -> Screen
      -> Validate
      -> Backtest
      -> Qualify
      -> Strategy Laboratory
      -> MT5 Backtest / Live Test
      -> Paper/Demo Testing
      -> Live Test Results
      -> Robust Shortlist
      -> AI Research
      -> Intelligent Mutation / New Research
      -> Repeat

Only after a strategy has survived sufficient testing should real-money live trading ever be considered.

AI integration is a FUTURE phase.
Do not redesign the core research engine around AI until the deterministic dashboard, persistence, filtering, validation, MT5 testing, and results pipeline are reliable.

13. CRITICAL LMSARENA STORAGE LESSON
=============================================================

Previous LMSArena attempts produced:

    "Something went wrong. Please try again."

The investigation established that the failure was associated with the LMSArena turn-end workspace snapshot.

The workspace had a strict approximately:

    128 MB

snapshot cap.

Duplicating persistent folders instead of moving them pushed the workspace above the limit.

Therefore:

NEVER duplicate large DATA folders in the workspace unnecessarily.

Use the local/tmp filesystem for large persistent data when supported.

The user specifically wants the following architecture going forward:

    GitHub repository
        |
        +-- code
        +-- CHATGPT/chatgpt.txt
        +-- DATA
               |
               +-- persistent research state

BUT when LMSArena builds/tests the project:

    CODE -> workspace
    DATA -> tmp storage

The DATA folder from GitHub must be placed in LMSArena's large temporary storage area rather than inside the 128 MB workspace.

The known LMSArena environment has approximately:

    20 GB tmp capacity

versus approximately:

    128 MB workspace snapshot limit

Therefore DATA should NOT be copied into the workspace if the platform supports placing it in tmp.

The code should reference the external DATA location through:

    EVOLUTIONARY_LAB_DATA_ROOT

or equivalent configuration.

23. PAPER TRADING
=============================================================

Paper trading exists because ordinary historical backtesting and forward/live simulation answer different questions.

Historical backtest:

    "What would this strategy have done on historical data?"

Paper/live test:

    "What does this strategy actually do when signals arrive sequentially under current market conditions and realistic execution?"

Paper trading can test:

    live signal timing
    execution assumptions
    spread
    slippage
    data latency
    position management
    real-time state
    missed signals
    broker/session differences
    risk management

Paper trading must NOT be eliminated merely because backtesting exists.

However, the project will also add:

    MT5 BACKTEST

because the user wants to test strategies through MetaTrader 5's strategy tester where practical.
