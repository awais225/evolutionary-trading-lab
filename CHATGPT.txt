end-to-end (separate DATA trees and SQLite DBs). The old repository

6. DATABASE ARCHITECTURE AND INSTRUMENT ISOLATION
-------------------------------------------------
Two namespaces:
(a) Global registry  DATABASE/hero1_registry.db
    tables: instruments, application_settings, global_events (+alembic_version)
(b) Per-instrument   <SYMBOL>/DATABASE/hero1.db  (XAUUSD, EURUSD, BTCUSD)
    tables: nodes, node_lineage, backtest_runs, deeptest_scenarios,
    deeptest_trades, research_tasks, research_findings, research_sources,
    live_sessions, live_configs, live_trades, approvals, activity_events
    (+alembic_version)
Rules: every instrument-scoped repository/route takes an explicit
`instrument`; unknown symbol → 404/422 before any file opened; NO silent
default anywhere; FK enforced; composite indexes on hot paths; ids repeat
across instrument DBs BY DESIGN (never assert on bare ids — see §9 / ISSUES-004).
Migrations: two independent Alembic setups inside packages/storage/alembic/;
parity test (create_all vs upgrade head) must pass.

DATA root: HERO1_DATA_ROOT (env). Default ~/.hero1/data (outside repo).
Inside-repo DATA root → hard refusal (ensure_outside_repository, engine.py).
Windows production target: D:\Hero1\DATA (see docs/WINDOWS_SETUP.md).

10. IMPORTANT ARCHITECTURAL DECISIONS AND REASONS
-------------------------------------------------
- Instrument isolation via separate SQLite files (not shared-table scoping):
  hard guarantee against cross-contamination; mirrors prod per-DATA-tree plan.
- Global registry DB separate from instrument DBs: cross-instrument queries
  (events, settings) stay possible; FK discipline per file.
- Durable-first events, WS fanout best-effort with replay: simple correctness;
  consumers use since_id — no DB polling, no lost ordering within a file.
- Live approval as separate `approvals` rows: AI/testing can never silently
  authorize live trading; enforced by schema + docs (Phase 5 contract).
- Provider-agnostic AI interface: Ollama first for local-first privacy; no
  cloud dependency required to develop.
- Explicit instrument on every scoped route/query; no ambient defaults.
- Phase-gated feature work: placeholder tabs shipped INSTEAD of fake demos.
- DATA outside repo, enforced at runtime, not just by convention/gitignore.
- Alembic inside packages/storage (single install unit), programmatic env.
