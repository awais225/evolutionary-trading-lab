# DeepTesting execution accuracy extension

## Implemented

- Extended the existing per-broker/per-symbol MT5 metadata snapshot path. On MT5 connection, existing refresh worker refreshes registered instruments; global instrument selection now asks the existing `/metadata/refresh` endpoint to refresh the selected symbol. The endpoint selects the exact symbol in Market Watch and supports a unique normalized prefix/suffix match; ambiguous matches fail rather than guessing. Snapshot payload retains normalized and raw symbol/tick values, account context, source, timestamp and fingerprint. DATA shows a grouped specification table with `MT5`, `DERIVED`, and `UNAVAILABLE` provenance labels, stale/connection state, and manual refresh; historical data and nodes remain in place.
- DeepTesting candle loads now preserve each candle's stored spread points. Runs can select historical-spread mode, convert points using the instrument's retrieved point size and use that bar's observation at entry and exit. Bid OHLC remains the engine contract: long entry Ask/exit Bid; short entry Bid/exit Ask; stops/targets use the corresponding closing side. Missing/invalid spread blocks by default; the applied fallback is configurable and emits a warning. Current spread is never subtracted a second time from P/L: quotes determine fills and the spread-cost figure is reported separately.
- Added commission per-side vs round-turn selection (mutually exclusive), point-based swap conversion with configured triple rollover weekday, adverse exit slippage, and recorded entry/exit quote sides, spread, commission, swap, slippage, equity-before-entry and executed-signal condition leaves. Current broker snapshot is persisted with each run config; historical specs remain unavailable unless there is an actual historical snapshot. Audit ZIP includes the snapshot, cost/quote data and condition evaluations recorded for executed signals; absent/non-signal evidence remains explicitly incomplete/unverified.
- DeepTesting Inspect presents BUY and SELL as compact responsive cards immediately above the existing weekday/session grid. Requested nine metrics remain in each always-visible card; prior directional metrics are retained under a disclosure.
- Engine version: 3.1.0. Existing stored runs and strategy fingerprints are not modified.

## Timestamp and spread evidence available locally

The local XAUUSD M1 source CSV has 100,057 data rows; all 100,057 imported M1 candles have non-null `spread` (range 0–40 points). First CSV wall time is `2026-07-07 21:41:00`; the import manifest's first canonical UTC timestamp is `2026-07-07 18:41:00`. This three-hour difference is explained by the existing importer applying `server_time.server_to_utc_epoch()` exactly once to CSV server-wall time (the same documented MT5 server-time conversion used at fetch ingestion); it was not introduced as a new blind shift. A live MT5 overlap comparison could not be made in this environment.

## Explicit limitations / pending work

- Exact C1#2 Run #2 reproduction remains **PENDING HISTORICAL REPRODUCTION**. The Run #2 ZIP and original C1 JSON were not present. Existing local Run #2 trade records could not be identified. No original run or strategy was overwritten, and no exact mismatch IDs are claimed.
- No connected MT5 terminal is available in this Linux sandbox. Live symbol/account values, symbol availability, broker-specific prefix resolution, account history commissions, current/stale refresh behavior, and XAUUSD/BTCUSD/Forex multi-instrument validation were not actually exercised against a terminal. The code fails on ambiguous symbol mapping and persists unavailable fields rather than inventing values.
- Current MT5 `symbol_info` tick values are used only when directly present and appropriate for the account; otherwise sizing refuses. The engine refuses non-Bid chart mode because Bid/Ask OHLC cannot be reconstructed honestly from Last OHLC alone. Swap conversion currently supports MT5 points mode and the explicit per-lot mode only; other MT5 swap modes require an explicit conversion and block rather than being approximated. UTC rollover is used for triple-swap weekday unless a broker-specific timezone rollover is supplied; rollover-time DST is not simulated.
- Commission schedules are not inferred from MT5 symbol info. If no explicit commission mode/rate is configured, the run labels `COMMISSION NOT CONFIGURED — incomplete-cost testing`. Historical deal commission import is not implemented in this extension.
- Condition leaves are logged at executed signal bars, not at all 100k+ non-signal candles. Rejected/not-recorded historical decisions remain `UNVERIFIED` / `INCOMPLETE EVIDENCE`; no logs are reconstructed.
- No market databases, generated datasets, Run #2 records, or strategy JSON were modified or added to source control.
